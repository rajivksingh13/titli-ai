🤖 Workshop Plan: How to Build, Test & Deploy AI Agents using Java and Google ADK

Audience: Java developers & power users comfortable with command line and Git

Duration: 1 Hour (60 minutes)

Format: 100% hands-on, instructor-led (live coding + follow-along)

Repo: java-ai-agent-adk in branch: java-ai-agents-google-adk (on GitHub)

🔮 Agenda at a Glance (60 minutes)

0–5 min — Kickoff & Architecture Primer

  • What is **Google ADK (Agent Development Kit)**? Components: Agents, Runner, Dev Web UI, AdkWebServer.
  • **Our Goal:** Run agents locally → containerize → deploy to Cloud Run (with health checks & env vars).

5–12 min — Project Setup (Local)

  • Clone repo & open in IntelliJ IDEA.
  • Walk through build.gradle (ADK deps, Spring Boot web starter, Java 17).
  • Verify **JDK 17** and Gradle wrapper, set **GOOGLE_API_KEY** locally (PowerShell / bash).
  • Quick peek at AdkLLMAgent and AdkWebServer.

12–27 min — Run & Test Locally (Dev Web UI)

  • ./gradlew clean runAdkServer to start AdkWebServer.
  • Open **Dev Web UI** (http://localhost:8080).
  • Create session, run a simple prompt, inspect logs (agent registry, sessions).
  • **Common fixes:** Ensure google-adk & google-adk-dev present, API key set, check schemas.

27–45 min — Containerize (Docker) & Smoke Test

  • Explain **Dockerfile layout**: build stage (Gradle build) → run stage (Temurin JRE 17).
  • Build image: docker build -t adk-ui .
  • Run local: docker run --rm -e PORT=8080 -e GOOGLE_API_KEY=$GOOGLE_API_KEY -p 8080:8080 adk-ui
  • Verify the Dev Web UI renders and agents load **inside the container**.

45–58 min — Deploy to Google Cloud Run

  • Push image (if using Artifact Registry): docker tag & docker push.
  • **Deploy to Cloud Run:** gcloud run deploy... (cover key flags: --allow-unauthenticated, --memory, --set-env-vars).
  • Health checks & startup probe notes; confirm URL works; create session in UI; tail logs.

58–60 min — Wrap-Up & Q&A

  • **Recap:** local → Docker → Cloud Run.
  • **Next steps:** Dedicated agent module, externalized config, CI/CD with Cloud Build.

💻 Detailed Hands-On Checklist

Prerequisites (preinstalled): Java 17, Gradle (or wrapper), IntelliJ IDEA, Docker Desktop, gcloud CLI (authenticated to project rajiv-ai), Artifact Registry enabled, Cloud Run enabled.

1) Clone & Inspect

git clone https://github.com/rajivksingh13/titli-ai.git
cd titli-ai/java-ai-agent-adk
# ensure you're on branch: java-ai-agents-google-adk

Skim: build.gradle (ADK deps), Agent classes, runAdkServer task.

2) Set API Key Locally

// PowerShell:

$env:GOOGLE_API_KEY="YOUR_ACTUAL_GEMINI_API_KEY"

// bash/zsh:

export GOOGLE_API_KEY="YOUR_ACTUAL_GEMINI_API_KEY"

3) Run the Dev Web Server Locally

./gradlew clean runAdkServer

Test http://localhost:8080, create a session, and send a prompt.

4) Build & Run Docker

docker build -t adk-ui .
docker run --rm -e PORT=8080 -e GOOGLE_API_KEY=$GOOGLE_API_KEY -p 8080:8080 adk-ui
Tip: If "Agent registry is empty" in the container, check the --adk.agents.source-dir path in your **Dockerfile's** ENTRYPOINT.

5) Push & Deploy to Cloud Run

# Push Image
gcloud auth configure-docker us-east1-docker.pkg.dev
docker tag adk-ui us-east1-docker.pkg.dev/rajiv-ai/containers/adk-ui:workshop
docker push us-east1-docker.pkg.dev/rajiv-ai/containers/adk-ui:workshop

# Deploy to Cloud Run
gcloud run deploy learning-assistant \
--image us-east1-docker.pkg.dev/rajiv-ai/containers/adk-ui:workshop \
--region us-east1 \
--allow-unauthenticated \
--cpu 1 --memory 1Gi --port 8080 \
--set-env-vars GOOGLE_API_KEY=$GOOGLE_API_KEY,GOOGLE_CLOUD_PROJECT=rajiv-ai,GOOGLE_CLOUD_LOCATION=us-east1

🔍 Talking Points & Stretch Goals

Slide-Friendly Talking Points (for instructor)

  • **Why Google ADK?** Rapid agent prototyping with Dev Web UI + clean abstractions.
  • **Local → Cloud parity:** Same Java app, just add a container boundary + Cloud Run infra.
  • **Observability:** Readiness/startup probes, log streams, session IDs, HTTP endpoints.
  • **Security:** Keep GOOGLE_API_KEY in Cloud Run env vars / Secret Manager.
  • **Scalability:** Cloud Run autoscaling; concurrency limits.
