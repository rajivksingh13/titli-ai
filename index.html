Incorrect or Partially Correct Statements vs Correct Definitions (with Examples)

1. Generative AI – Vague or Missing Definition

❌ Incorrect / Partially Correct (as presented):

  • Generative AI was not clearly defined.
  • Focused on “building cool stuff” and “using prompts.”
  • Did not explain what makes a system generative.

✅ Correct Definition:

Generative AI refers to neural network models designed to generate new content such as text, images, audio, video, and code. They learn probability distributions from vast datasets and generate outputs by predicting likely next tokens, pixel structures, or frame sequences.

Simple Example: A model trained on millions of recipes can generate a new recipe following patterns it learned.

2. LLM (Large Language Model) – Misdefined or Oversimplified

❌ Incorrect / Partially Correct (as presented):

  • LLMs are “trained to query on top of your questions.”
  • Suggests LLMs learn from real-time user queries.
  • Confuses LLMs with image/video generative models.

✅ Correct Definition:

LLMs are Transformer-based neural networks pre-trained on vast text corpora. They do not learn from individual prompts. They generate text by predicting the most likely next token.

Simple Example: Input: “Once upon a…” → Output: “time,” “night,” “dream.”

3. Misrepresentation of RAG (Retrieval-Augmented Generation)

❌ Incorrect / Partially Correct (as presented):

  • Described as “brick table augmented generation.”
  • Positioned as a frontend prompt processor.
  • Vague explanation of retrieval and grounding.

✅ Correct Definition:

RAG is a backend architecture pattern. It retrieves relevant documents from a vector database, augments the user prompt, and produces grounded, accurate outputs using the LLM.

Simple Example: Query: “What is ABC Company’s refund policy?” → System retrieves the policy and sends it with the prompt to the LLM.
Analogy: LLM = customer representative; retriever = assistant who fetches documents from the back office.

4. LoRA (Low-Rank Adaptation) – Completely Misunderstood

❌ Incorrect / Partially Correct (as presented):

  • Described as an output ranking/selection mechanism.
  • Incorrectly connected to weather prediction ranking.

✅ Correct Definition:

LoRA is a Parameter-Efficient Fine-Tuning (PEFT) method. It adapts large models by training small low-rank matrices, not by ranking outputs.

Simple Example: Fine-tune an LLM for legal analysis or medical summarization using only ~1–2% new parameters.

5. Vector Embeddings and Vector Databases – Confused Concepts

❌ Incorrect / Partially Correct (as presented):

  • Claims vector DBs store raw images/screenshots.
  • Embeddings equated to vector DB functionality.

✅ Correct Definition:

Embeddings are numerical representations of text, images, or audio. Vector databases store these embeddings and perform similarity search.

Simple Example: Query: “dog wearing sunglasses” → Convert query to embeddings → Compare with stored embeddings → Return closest results.

6. Tokens – Misdefined Purpose

❌ Incorrect / Partially Correct (as presented):

  • Tokens described as managing service queries.
  • Confused with usage tracking mechanisms.

✅ Correct Definition:

A token is a unit of text the LLM processes. Tokens affect cost, speed, and context window size. They do not manage queries.

Simple Example: “Elephant” → 2 tokens (“ele”, “phant”), “AI” → 1 token.

7. Hallucinations – Incorrect Explanation

❌ Incorrect / Partially Correct (as presented):

  • Incorrect numeric example unrelated to hallucinations.
  • Suggested hallucinations come from misunderstanding inputs.

✅ Correct Definition:

Hallucinations occur when an LLM produces confident but factually incorrect or fabricated information due to statistical prediction, not user input misunderstanding.

Simple Example: “Who won the 2027 World Cup?” → Model answers with made-up results.

8. Fine-Tuning – Incorrect Analogy

❌ Incorrect / Partially Correct (as presented):

  • Compared to customizing Python libraries.
  • Treated as configuration rather than model training.

✅ Correct Definition:

Fine-tuning modifies a pre-trained model's internal weights using domain-specific datasets. This requires GPUs, training loops, and labeled data.

Simple Example: Fine-tune a base LLM to become a legal assistant or bilingual translator.

9. In-Context Learning (ICL) – Misunderstood

❌ Incorrect / Partially Correct (as presented):

  • Framed as backend teams learning user behavior.
  • Incorrectly implies permanent learning from queries.

✅ Correct Definition:

ICL allows an LLM to learn from examples inside a prompt during inference. No weights are updated; learning is temporary.

Simple Example: Provide translation pairs → model infers pattern → translates new text.

10. Image Generation – Oversimplified and Incorrect

❌ Incorrect / Partially Correct (as presented):

  • Described as embedding rendering in frontend.
  • Misses role of diffusion/GAN architectures.

✅ Correct Definition:

Image generation uses diffusion models, GANs, or decoders. Embeddings guide generation; the frontend only displays the final output.

Simple Example: Blueprint = prompt; Construction = diffusion; Finished house = final image.

11. Misplacement of RAG, Vector DB, and Prompting in Architecture

❌ Incorrect / Partially Correct (as presented):

  • RAG, vector DB, and retrieval placed in frontend.
  • Prompting treated as a hallucination fix.

✅ Correct Architecture:

LayerResponsible For
FrontendUI, forms, displaying responses
BackendAPIs, RAG, retrieval, vector DB lookups
Model LayerLLM inference, embeddings, fine-tuning

Prompting can reduce hallucinations but cannot eliminate them. RAG provides true grounding.

12. Overall Pattern of Issues

The training session contained several technical inaccuracies:

  • Confusion between training and inference
  • Incorrect placement of RAG, LoRA, embeddings, tokens
  • Misunderstanding of LLM usage
  • Oversimplified or incorrect analogies
  • Inaccurate mental models of generative AI systems

These issues may lead students to misunderstand modern AI concepts and struggle with real-world implementations.
